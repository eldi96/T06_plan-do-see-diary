## 최신 규칙 — 페이지마다 12개/7번째 분할 (2026-10-14)

아래의 기존 ‘6개 페이지’ 규칙은 이 규칙으로 대체한다. 한 페이지 최대12개, 그 페이지의1~6개는 긴1열/7~12개는 반폭2열. 13번째는다음페이지1개로 시작하고, 전체19개일 때둘째페이지7개가되어 다시2열이다. 목록 컨테이너1000px미만은 읽기/터치를 위해1열을 유지한다. 수동 카드보기는 기존 카드 형태를 유지하며 페이지당12개다.

| Before | After | Why |
|---|---|---|
| 7번째 계획부터 다음 페이지 | 12개까지 한 페이지, 13번째부터 다음 페이지 | 계획을 한눈에 더 많이 확인 |
| 목록 폭 항상 전체 너비 | 페이지별7개부터 반폭2열 | 기존 행 디자인을 유지하며 공간 활용 |
| 한 페이지의 고정 모양 | 다음페이지도1~6개1열/7개부터2열 반복 | 사용자 지정 누적 규칙 |

domain/plan-pagination.ts로경계값공유. 실제 단위테스트2개:1/6/7/12/13/18/19/24/25 및삭제/빈검색보정. 타입검사·신규파일 lint·빌드통과. 격리DB 브라우저에서6개1563px1열→UI추가7개775.5px씩2열/넘침없음,13개첫페이지12·둘째페이지1개1563px확인. 현재사용자7개도2열확인.900/390px문서/목록넘침없음. 검수자readonly승인. 사용자기록변경/배포없음.

Anime.js는기존planIDs변경시배치를움직이므로6→7추가및두번째페이지6→7도이동한다. 페이지·검색조작은기존대로즉시처리한다. 최신화면 outputs/plan-split-12.png.

선택·검색·페이지 이동에는 위치 애니메이션을 넣지 않는다. 버튼 접근성 이름/aria-pressed, 빈 결과 검색 해제, 삭제 후 페이지 범위 보정, 기존 수정·이력·삭제 콜백을 유지했다. 검색·페이지 이동은 선택한 계획과 DB 값을 변경하지 않는다. 보기 선택은 현재 탭 세션 상태이며 탭 재진입시 기본 규칙을 적용한다.

실제 검증: TypeScript, 신규 컴포넌트 ESLint, 최종 빌드 통과. 사용자 계획 8개에서 기본 목록 6개/다음 페이지2개, 네트워크 검색2개, 카드 전환2개, 검색 없음·해제, 검색 후 선택 계획 유지 확인. 900/800/390px에서 목록 scrollWidth=clientWidth, 문서 가로 넘침 없음. 390px 검색 입력16px. 검수자가 지적한 태블릿 최소 열 너비를 보완 후 다시 확인했다. 실제 휴대전화는 미검증.
