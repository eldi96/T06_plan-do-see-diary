# 제출 문구 초안 — 공개 URL과 실제 자료 확인 전

현재 로컬은 제출 URL이 아니다. 배포 금지 요청을 유지한다. 아래 대괄호 부분은 공개 결과물/소스 주소와 사용자 확인 후 채운다.

## 확인 방법 4줄
어디로 가나요: [로그인 없이 열리는 결과물 URL]에서 ‘계획과 루틴’을 엽니다.
세 단계 안에 무엇을 하나요: 계획 선택 → 할 일의 실행 기록 확인 → 돌아보기 숫자 클릭.
무엇이 보이면 통과인가요: 실제 계획의 할 일·실행 기록이 연결되고 집계 숫자에 해당하는 근거가 보이며 새로고침 뒤 유지됩니다.
안 될 때는 무엇이 보이나요: 오류 안내와 다시 시도 버튼이 표시되며 저장 실패 시 입력이 유지됩니다.

## AI와 내 판단 3줄 — 대화에 근거한 초안, 사용자 최종 확인 필요
AI에게 맡긴 일: 설계·구현·코드 검수와 분리된 테스트 DB를 통한 기능 검증.
내가 직접 판단한 일: 어두운 배경·민트 디자인과 학습 체크리스트 방향, 공부 시작일을 직접 설정하는 방식.
AI 말을 따르지 않은 일: 시간 중심으로 기록하는 초기 화면 대신 하루 학습 내용을 확인하는 체크리스트를 선택했고, 제출 규칙에 필요한 예상·실제 시간은 유지했습니다.

## 아직 필요한 제출 조건
- 공개 결과물 URL 및 최종 소스 URL을 새 시크릿 창에서 로그인 없이 확인(C01).
- 사용자 실제 계획 1개·할 일 5개·실행 기록 3개, 전부 0이 아닌 돌아보기(C78–81).
- 운영 DB의 새로고침·내보내기·공개 접근 검증. 로컬 격리 테스트를 운영 실자료 증거로 쓰지 않는다.
- 원격 소스/배포 파일/응답/콘솔의 최종 비밀값 점검(C58). 현재 검증 범위는 ASSIGNMENT_AUDIT.md를 따른다.
